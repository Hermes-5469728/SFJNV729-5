# 绝对颗粒度评估·造轮子前的灵魂三问

在写每一行核心代码前问自己:

1. 这个逻辑如果变了，是因为业务变了，还是因为我想换个写法？
   业务变了 → 自己写
   想换写法 → 用开源库

2. 这个功能在Stack Overflow上是否有超过100个赞的解决方案？
   有 → 抄过来并理解它
   没有 → 自己写（可能是第一个遇到这个问题的人）

3. 如果这段代码明天要交给实习生维护，他能在10分钟内看懂吗？
   能 → 继续写
   不能 → 简化它或加注释

总结: 对通用能力(网络/存储/日志)像吝啬鬼，能不用自己写的就不用
       对业务逻辑(状态机/编排/决策)像工匠，精雕细琢寸土必争
