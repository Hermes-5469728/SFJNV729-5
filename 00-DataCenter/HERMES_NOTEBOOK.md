## 黑话集

### 核心概念

**架构锚点** — 钉死的参照点，不能随便移。
- store_truth 是知识入库的唯一通道——这就是一个锚点
- 锚点可以加，但不能改。要改就加新版本，旧版本标记失效

**治理管道（Governance Pipeline）** — 流水线上的质检工位。
- 你的输入经过 encoding → syntax → semantic → security 四个工位检查
- 每个工位只做一件事，做完了传给下一个
- 不合格的打回去重做（corrector ×3）

**双头架构** — 两个模块做同一件事，互相不知道对方存在。
- SubAgent 和 AC Platform 现在就是双头
- 同一请求可能得到两种处理结果——调试查两边日志
- 解法：事件总线 + 统一调度

**配置漂移（Configuration Drift）** — 同一份配置在两个地方变成不同版本。
- `{USER_HOME}\ac\` 和 `HERMES-DATE/HERMES-DATE/` 的代码不同步
- 不是 bug，是比 bug 更隐蔽的"环境分裂"
- 解法：统一单一源码目录 + 自动同步

### 架构决策

**E/D/S/Q**: 四层架构的缩写。
- E = Encoder（编码层）：洗数据
- D = Dispatch（调度层）：配专家
- S = Scheduler（编排层）：管流程
- Q = QA（治理层）：查质量

**1+N 架构**: 1 个核心平台 + N 个独立模块。
- 1 = AC Platform（入口 + 流水线 + 治理 + 数据库）
- N = Orchestrator / Anchor Engine / Case Center / Governance 等

**流 A / 流 B**: 双流设计。
- 流 A：简单查询走快速路径（单轮 dispatch，秒级返回）
- 流 B：复杂任务走编排路径（多 Agent 协作，分钟级）
- Router 根据输入长度和关键词自动选择

### 技术术语

| 术语 | 人话 |
|------|------|
| **EAV 模型** | 把知识拆成"实体-属性-值"三段。比如（AC平台，架构，E/D/S/Q）|
| **L5 标注** | 给输出打标签：谁生成的、什么时候、来源是什么。类似食品包装上的生产日期和配料表 |
| **熔断器** | 发现危险自动切电源。连续失败 3 次就熔断，不让请求继续往里送 |
| **回滚** | 发现走错了，退回上一个岔路口 |
| **Session** | 一次对话的完整生命周期。从你发"你好"到你说"再见"，算一个 session |
| **P1-P5** | 优先级从高到低。P1 是安全问题必须马上处理，P5 是可有可无 |
| **13 态状态机** | Orchestrator 里任务的 13 种状态（创建→排队→执行→验证→完成→失败→回滚等）|
| **TTL** | 有效期。数据存太久没人验证，自动降级或清理 |
| **Jaccard 相似度** | 两个文本有多像——看它们用了多少个相同字符或词组 |
| **n-gram** | 把文本切成 n 个字符一组来比较。比"完整字符串匹配"更灵活 |

## 架构 Bug 与修复

### 2026-05-13 · 三关修复

#### 第一关：幻觉审计

**HallucinationAuditor** — 运行时幻觉检测引擎。
- 在 AI 输出返回给用户之前，逐句检查
- 检查项：低置信度表述（"可能""大概"）、引用缺失、疑似幻觉模式
- 标记但不拦截（当前设计），将来可以配置为拦截

**核心不变量 #2**: 所有输出必须携带中英双语幻觉声明。
- 之前写在架构图里，现在写在测试用例的断言里
- 任何破坏这个规则的代码改动，会被测试挡住

#### 第二关：事实锚点

**L2 空壳** — 之前验证逻辑只写了骨架，没写血肉。
- validate_truth() 的 L2 检查之前只有"太简化的检测，不做实质性判断"
- 修复后：锚点库比对 + 数字冲突检测 + 真值重复 + 极性反转

**极性反转** — 一个说"是"，一个说"不是"，自动识别为矛盾。
- 比如输入说"图灵测试是 1960 年提出的"，锚点库说是 1950 年
- 系统自动标记 FAIL

#### 第三关：分类兜底

**分类兜底** — 关键词匹配不到时，不直接返回"查无此人"。
- 第一层兜底：语义匹配（n-gram + Jaccard 相似度）
- 第二层兜底：category_fallback（按分类关键词匹配）
- 第三层兜底：unclassified（全部都不匹配时）

**多标签支持**: 一个输入可以同时匹配多个专家。
- "焦虑失眠"同时命中心理和情绪管理
- 之前只返回 top 2，现在返回所有匹配结果

### 2026-05-13 · 架构复盘（12 个问题）

#### P0 级（威胁生产正确性）

| 问题 | 一句话解释 |
|------|-----------|
| P0-1 双份代码 | 同一份代码在两个目录有不同版本，跑起来用的是哪个靠运气 |
| P0-2 硬依赖阻塞测试 | 一导入模块就要加载整个包，独立测一个函数都不行 |
| P0-3 escalate 虚构 | 代码里写了"升级到编排模式"的字段，但没人监听它 |
| P0-4 绕过治理 | 我写文件时不经过质量检查，等于产品出厂不质检 |

#### P1 级（削弱效率和智能）

| 问题 | 一句话解释 |
|------|-----------|
| P1-1 知识库断裂 | 数据库里存了真值，但调度器查都不查它 |
| P1-2 auditor 未集成 | 幻觉检测写好了，但没接进流水线 |
| P1-3 SubAgent 隔离 | 两条 AI 通道各自跑各自的，结果不汇总 |
| P1-4 治理消失 | 我发现的问题只在这个对话里有，下次 session 就忘了 |

#### P2 级（多用户时爆发）

| 问题 | 一句话解释 |
|------|-----------|
| P2-1 无 Gate | 任何输入都直通核心，没人检查值不值得处理 |
| P2-2 无 CI/CD | 测试靠手动跑，部署靠手动复制，回滚靠手动 git |
| P2-3 队列不可靠 | 消息存在内存里，进程一崩全丢 |
| P2-4 模块间无协议 | 模块之间通信没有统一格式，全靠默契 |
