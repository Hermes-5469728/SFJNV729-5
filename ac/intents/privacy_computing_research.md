# 意图: 隐私计算在 Jarvis 中的适用性研究

## 目标
调研并对比本地差分隐私、联邦学习、同态加密在 Jarvis 记忆分析中的适用性，不编写代码，输出技术选型报告。

## 背景 · 当前缺失的后果
- Jarvis 记忆库（`assistant/memory.py`）存储了大量个人偏好、对话历史、行为模式
- 当前所有记忆以明文存储在本地 SQLite (`ac_platform.db`)
- 如果未来需要：
  - 分析记忆数据以优化 AI 响应质量
  - 与他人共享部分知识库
  - 在多租户环境下隔离记忆
- 在这些场景下，原始数据的隐私保护成为硬性要求

## 关键约束
1. **算法必须可解释** — 隐私保护机制的效果必须可被审计，不能是"相信平台"
2. **不依赖云端服务** — 所有隐私计算必须在本地完成
3. **性能可接受** — 不能因隐私计算导致查询延迟超过 1 秒
4. **与 R10 对齐** — 任何本地数据操作不能被云服务商隐式增强

## 调研范围

### 1. 本地差分隐私 (Local Differential Privacy)
- **适用场景**: 记忆统计查询（如"用户最常问哪类问题？"）
- **原理**: 在原始数据上加噪，使得单个记忆无法被还原
- **关键参数**: ε (隐私预算)，越小越隐私但越不准确
- **待调研**:
  - Google RAPPOR / Apple Differential Privacy 的本地实现
  - ε 值对记忆查询准确度的影响曲线
  - 能否对 SQLite 查询结果自动加噪？

### 2. 联邦学习 (Federated Learning)
- **适用场景**: 多 Jarvis 实例间共享模型更新，不共享原始数据
- **原理**: 各实例本地训练，仅上传模型梯度
- **待调研**:
  - 单机场景下联邦学习的必要性（无其他实例可联邦）
  - 模拟多用户场景时，本地联邦模拟的可行性
  - PySyft / OpenFL 等框架的本地模式

### 3. 同态加密 (Homomorphic Encryption)
- **适用场景**: 对加密记忆执行计算，无需解密
- **原理**: 在密文上直接计算，结果解密后与明文计算结果一致
- **待调研**:
  - Microsoft SEAL / TenSEAL 对文本数据的适用性
  - 全同态 vs 部分同态的选择
  - 加密后的查询延迟是否可接受（>1s?）

### 4. 安全多方计算 (SMPC)
- **适用场景**: 多用户在不暴露各自数据的前提下协同计算
- **待调研**:
  - 是否存在不需要其他参与方的本地 SMPC 模式
  - 是否过度工程化（当前无多用户场景）

### 5. 边缘方案
- **可信执行环境 (TEE)**: Intel SGX / AMD SEV — 依赖特定硬件
- **数据脱敏**: 比加密更轻量，对记忆库做 k-匿名化
- **审计日志**: 不阻止数据访问，但记录所有访问行为（已有 R8）

## 评估维度

| 维度 | 差分隐私 | 联邦学习 | 同态加密 | SMPC |
|------|---------|---------|---------|------|
| 隐私强度 | 中等 | 高 | 极高 | 极高 |
| 计算开销 | 低 | 中 | 高 | 极高 |
| 实现复杂度 | 低 | 高 | 极高 | 极高 |
| 本地可行性 | ✅ 是 | ⚠️ 需多实例 | ✅ 是 | ❌ 需多方 |
| 适用单用户 | ✅ 是 | ❌ 否 | ✅ 是 | ❌ 否 |
