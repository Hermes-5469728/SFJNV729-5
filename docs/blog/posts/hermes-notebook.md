## 黑话集

### 核心概念

**架构锚点** —— 钉死的参照点，不能随便移。

- `store_truth` 是知识入库的唯一通道——这就是一个锚点
- 锚点可以加，但不能改。要改就加新版本，旧版本标记失效

**治理管道（Governance Pipeline）** —— 流水线上的质检工位。

- 输入经过 encoding → syntax → semantic → security 四个工位检查
- 每个工位只做一件事，做完了传给下一个
- 不合格的打回去重做（corrector ×3）

**双头架构** —— 两个模块做同一件事，互相不知道对方存在。

- SubAgent 和 AC Platform 就是双头
- 同一请求可能得到两种处理结果——调试查两边日志
- 解法：事件总线 + 统一调度

**配置漂移（Configuration Drift）** —— 同一份配置在两个地方变成不同版本。

- 运行目录和 git 仓库的代码不同步
- 不是 bug，是比 bug 更隐蔽的"环境分裂"
- 解法：统一单一源码目录 + 自动同步

### 架构决策

**E/D/S/Q**: 四层架构的缩写。

| 层 | 含义 | 职责 |
|----|------|------|
| E = Encoder | 编码层 | 洗数据 |
| D = Dispatch | 调度层 | 配专家 |
| S = Scheduler | 编排层 | 管流程 |
| Q = QA | 治理层 | 查质量 |

**1+N 架构**: 1 个核心平台 + N 个独立模块。

- 1 = AC Platform（入口 + 流水线 + 治理 + 数据库）
- N = Orchestrator / Anchor Engine / Case Center / Governance 等

**流 A / 流 B**: 双流设计。

- 流 A：简单查询走快速路径（单轮 dispatch，秒级返回）
- 流 B：复杂任务走编排路径（多 Agent 协作，分钟级）
- Router 根据输入长度和关键词自动选择

## 三关修复记录

### 第一关：幻觉审计

**HallucinationAuditor** — 运行时幻觉检测引擎。

- 在 AI 输出返回给用户之前，逐句检查
- 检查项：低置信度表述（"可能""大概"）、引用缺失、疑似幻觉模式

### 第二关：事实锚点

**L2 锚点引擎** — 之前验证逻辑只写了骨架，没写血肉。

- 锚点库比对 + 数字冲突检测 + 真值重复 + 极性反转
- 一个说"是"，一个说"不是"，自动识别为矛盾
- 比如输入说"图灵测试是 1960 年提出的"，锚点库说是 1950 年，系统自动标记 FAIL

### 第三关：分类兜底

**分类兜底** — 关键词匹配不到时，不直接返回"查无此人"。

- 第一层兜底：语义匹配（n-gram + Jaccard 相似度）
- 第二层兜底：category_fallback（按分类关键词匹配）
- 第三层兜底：unclassified（全部都不匹配时）
