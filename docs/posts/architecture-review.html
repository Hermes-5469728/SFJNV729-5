2026-05-13AC复盘

架构风险复盘 · 12 个问题诊断

按发现的时间线记录所有架构级问题，每个包含发现场景、根因、工业对应缺陷、当前影响。

P0 · 威胁生产正确性

问题一句话
P0-1 双份代码同一份代码在两个目录有不同版本，跑哪个靠运气
P0-2 硬依赖阻塞测试一导入模块就加载整个包，独立测一个函数都不行
P0-3 escalate 虚构升级字段写了但没人监听，消息静默丢弃
P0-4 绕过治理Write/Edit 不经过四层质检流水线

P0-1 · 运行目录与仓库分裂

  • 发现：运行目录和 git 仓库分离。core.py dispatch 改造、validator.py L2 修复只改了一边。
  • 根因：没有明确的源码主目录，运行与开发环境未统一。
  • 缺陷：配置漂移 / 环境不一致
  • 后果：从不同目录启动执行不同版本代码，已构成"分裂脑"。

P0-2 · 顶层硬依赖阻塞测试

  • 发现：governance/__init__.py 第 3 行 from ac.governance.checker import ... 导致任何 import 都触发全包依赖。
  • 根因：包初始化时执行重依赖导入，违反"导入应无副作用"。
  • 后果：测试无法独立运行，新人或 CI 环境直接失败。

P0-3 · escalate 升级通道不存在

  • 发现：第三关测试中添加了 escalate 字段，但 orchestrator 未监听。
  • 根因：契约未实现，测试字段是"愿望"而非真契约。
  • 后果：无法分类的消息被静默丢弃，生产环境直接丢失业务请求。

P0-4 · 对话端绕过治理管道

  • 发现：Write/Edit 直接操作文件系统，全程不经 G0-G3。
  • 根因：治理管道与对话端工具链没有集成，治理仅守卫 CLI/Web 入口。
  • 后果：文件内容可含幻觉、矛盾，无任何自动检查。

P1 · 削弱效率和智能

问题一句话
P1-1 知识库断裂数据库里存了真值，调度器查都不查
P1-2 auditor 未集成幻觉检测写好了，没接进流水线
P1-3 SubAgent 隔离两条 AI 通道各自跑，结果不汇总
P1-4 治理消失发现的问题只在这个对话里有，下次 session 就忘了

P1-1 · 真值知识库与核心链路断裂

输入 → store_truth() → validate_truth() L0/L2/L5 → ac_truth
  │                                                     │
  │                              (缺) dispatch 不读      │
  │                              (缺) orchestrator 不查  │
  │                              (缺) auditor 不引用     │
  └──────── 知识入库后即被遗忘 ──────────────────────────┘

P2 · 多用户时爆发

问题一句话
P2-1 无 Gate任何输入直通核心，没人检查值不值得处理
P2-2 无 CI/CD测试靠手动跑，回滚靠手动 git
P2-3 队列不可靠消息存在内存里，进程一崩全丢
P2-4 无协议模块通信没有统一格式，全靠默契

工具作用

Event Bus统一模块间通信——海关模式
