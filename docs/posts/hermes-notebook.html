黑话集

核心概念

架构锚点 —— 钉死的参照点，不能随便移。

  • store_truth 是知识入库的唯一通道——这就是一个锚点
  • 锚点可以加，但不能改。要改就加新版本，旧版本标记失效

治理管道（Governance Pipeline） —— 流水线上的质检工位。

  • 输入经过 encoding → syntax → semantic → security 四个工位检查
  • 每个工位只做一件事，做完了传给下一个
  • 不合格的打回去重做（corrector ×3）

双头架构 —— 两个模块做同一件事，互相不知道对方存在。

  • SubAgent 和 AC Platform 就是双头
  • 同一请求可能得到两种处理结果——调试查两边日志
  • 解法：事件总线 + 统一调度

配置漂移（Configuration Drift） —— 同一份配置在两个地方变成不同版本。

  • 运行目录和 git 仓库的代码不同步
  • 不是 bug，是比 bug 更隐蔽的"环境分裂"
  • 解法：统一单一源码目录 + 自动同步

架构决策

E/D/S/Q: 四层架构的缩写。

层含义职责
E = Encoder编码层洗数据
D = Dispatch调度层配专家
S = Scheduler编排层管流程
Q = QA治理层查质量

1+N 架构: 1 个核心平台 + N 个独立模块。1 = AC Platform（入口 + 流水线 + 治理 + 数据库）；N = Orchestrator / Anchor Engine / Case Center / Governance 等。

流 A / 流 B: 双流设计。流 A：简单查询走快速路径（单轮 dispatch）；流 B：复杂任务走编排路径（多 Agent 协作）。Router 根据输入长度和关键词自动选择。

三关修复记录

第一关：幻觉审计

HallucinationAuditor — 运行时幻觉检测引擎。在 AI 输出返回给用户之前，逐句检查低置信度表述、引用缺失、疑似幻觉模式。

第二关：事实锚点

L2 锚点引擎 — 锚点库比对 + 数字冲突检测 + 真值重复 + 极性反转。输入说"图灵测试是 1960 年提出的"，锚点库说是 1950 年，系统自动标记 FAIL。

第三关：分类兜底

关键词匹配不到时，不直接返回"查无此人"。三层兜底：语义匹配（n-gram + Jaccard）→ category_fallback → unclassified。
