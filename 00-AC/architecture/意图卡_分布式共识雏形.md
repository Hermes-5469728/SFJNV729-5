# 意图卡 · 分布式共识雏形

## 模块名
`consensus` — 多 AI 矛盾裁决器 · 温差共识 V0

## 目标
当多个 AI（DeepSeek、千问、文心、Kimi）对同一事实给出矛盾结论时，不依赖人工做仲裁，而是通过温差比对数个模型输出的语义一致性，自动判定可信度排序。

## 背景
- **宪法规则**: AC 不决策，选择权在用户 — 但用户不可能每次都读 4 份 AI 输出再手动比对。需要一个预判层，把矛盾点标出来，让用户的"选择权"用在刀刃上
- **猎鬼发现**: 架构审计 (2026-05-13) 第 6 项 — HallucinationAuditor 未集成。更根本的问题是：单个审计器只能判定"这句话有多自信"，不能判定"五个 AI 对同一问题的矛盾结论中谁更可信"
- **为什么需要**: dual_inference (t=0 vs t=0.7) 已经证明：同一个模型的不同温度参数会产生矛盾输出。扩展到多模型，矛盾只多不少。AC 需要的是一个"矛盾的发现者"，而不是"矛盾的裁决者"

## 输入
| 参数 | 类型 | 说明 |
|------|------|------|
| `query` | `str` | 原始问题 |
| `responses` | `list[dict]` | 多模型/多实例的响应: [{model_id, temperature, content, confidence}] |
| `consensus_threshold` | `float` | 共识阈值 (0~1)，多少比例的模型同意才算共识，默认 0.6 |

## 输出
```python
{
    "query": str,
    "total_models": int,          # 参与共识的模型数
    "consensus_reached": bool,    # 是否达成共识
    "agreement_score": float,     # 一致性分数 (0~1)
    "clusters": [                 # 意见集群
        {
            "cluster_id": str,
            "models": list[str],  # 属于此集群的模型
            "summary": str,       # 此集群的核心观点
            "confidence": float,  # 此集群的平均置信度
        }
    ],
    "contradictions": [           # 检测到的矛盾
        {
            "type": str,          # factual / logical / numerical / omission
            "cluster_a": str,     # 矛盾方 A 的集群 ID
            "cluster_b": str,     # 矛盾方 B 的集群 ID  
            "detail": str,        # 矛盾描述
            "severity": str,      # minor / moderate / critical
        }
    ],
    "needs_human": bool,          # 是否需要人工介入
    "recommendation": str | None, # 如果有共识，给出推荐
}
```

## 关键约束
1. **不替用户决策** — consensus 只做矛盾发现和可信度排序，不自动选择"正确答案"
2. **必须对接 HallucinationAuditor** — 每个模型的 response 先跑幻觉审计，置信度分数作为共识计算的输入权重
3. **必须对接 dual_inference** — 同一模型的双实例温差已在此层之下处理。共识层看到的是"每个模型的最优输出"
4. **矛盾不可静默** — 检测到 critical 级别矛盾时，必须标记 `needs_human=True` 并高亮
5. **结果写入 `governance_events`** — event_type=`consensus_complete` / `consensus_conflict`
6. **最多 4 个模型同时参与** — 与适配器层注册的 5 个模型对应（deepseek-free 为主推理，其他为比对源）

## 已知难点
1. **语义等价判定** — "布洛芬可以退烧" 和 "布洛芬具有解热作用" 是否矛盾？需要 sentence-transformers 嵌入相似度，但本地 embedding 模型可能不够准
2. **模型能力不对称** — deepseek-free (671B MoE) 和 qwen-free (7B) 对同一问题的回答质量天然不同。简单多数投票会淹没强模型的正确意见。需要模型能力加权
3. **矛盾粒度** — "焦虑会导致失眠吗？" → 模型 A 说"会，因为有生理机制"，模型 B 说"会，但主要是心理因素"——这不矛盾，只是侧重点不同。如何区分"真正的矛盾"和"同义表达"？
4. **API 成本** — 一次共识检查需要调用 4 个模型的 API。如果用户问 10 个问题，就是 40 次 API 调用。免费层的 rate limit 可能不够
5. **与 robust_inference.py 的关系** — `robust_inference.py` 已有"多模型多数投票"功能，共识层是替代它还是增强它？
