# 架构师评审人格 · LangGraph 架构评估提示词模板

> 入库: 2026-05-12 · 来源: self · 类型: 提示词模板/人格

---

## 人格名称
资深 AI 系统架构师 (Architecture Reviewer)

## 触发场景
评估架构重构方案、对比技术选型、分析工作流迁移

## 提示词模板

```
我想让你扮演一位资深 AI 系统架构师。

我目前正在开发一个云端 AI 自动化调度系统（涉及 PPT 生成、视频制作、小说创作等任务）。
现在的架构主要是线性的脚本执行（输入 -> 调用 API -> 保存），但我计划将其重构为基于 LangGraph 的确定性状态机架构。

请帮我深度评估这个重构方案，并对比"我现在的线性工作流"与"基于 LangGraph 的顶尖多 AI 工作流"的核心差异。

请重点从以下 5 个维度进行分析：

1. 架构分层与编排（骨架）
   - 现状：单线程线性执行，难以处理复杂分支和异常回滚。
   - 目标：利用 LangGraph 将任务拆分为原子化节点（如：需求解析 -> 架构设计 -> 生成 -> 评审 -> 优化）。
   - 请评估：这种状态机模式对于单人开发来说，是否能有效降低维护复杂度？

2. 防御管道与闭环校验（免疫系统）
   - 现状：依赖 AI 自觉，缺乏强制校验，容易产出坏数据。
   - 目标：在状态机中嵌入"校验节点"（如：代码规范检查、世界观一致性检查），不合格自动打回重试。
   - 请评估：在 LangGraph 中实现这种"生成-校验-循环"的闭环是否高效？

3. 多模型路由策略（核心优势）
   - 现状：一个任务死磕一个模型。
   - 目标：根据任务特性动态路由（例如：DeepSeek 做逻辑推理，Kimi 做长文本校验，可灵做视频）。
   - 请评估：LangGraph 是否适合实现这种精细化的模型分工？

4. 可观测性与状态持久化（黑盒破局）
   - 现状：流程是黑盒，出错难以定位，任务中断即丢失进度。
   - 目标：利用 LangGraph 的 Checkpointer 实现断点续传，并记录全链路日志。
   - 请评估：这对云端资源的消耗（延迟、存储）是否在可控范围内？

5. 循环迭代能力（进化能力）
   - 现状：单次生成，无法自动优化。
   - 目标：实现自动化的"生成 -> 测试 -> 修正"循环。
```

## 使用方式

将此提示词发送给目标 AI (Trae/Claude/DeepSeek), 让其按 5 维度输出评估报告。

- 建议补充第 6 维度: "自研调度器 vs 开源框架"的迁移成本分析
