## 一、顶层只有两条路

```
轨道一: 独立项目 (Standalone) - 离线单机
  一个 exe/文件夹, 医生打开就能用, 不需要联网, 不依赖任何平台
  里面打包了四个能力:
    ├── AC决策        → 帮你判断"这个事该不该做"
    ├── 信息处理中心   → 帮你从本地文件里搜出你要的东西
    ├── 辅助个人发展   → 记录你的学习进度, 到点提醒你该学什么
    └── 个人创意工坊   → 给你画板、导出工具, 想做什么做什么

轨道二: 平台 1+N (Platform) - 联网协同
  一个核心平台 (1), 挂载 N 个垂直业务模块
  当前 N = DADS-Medical (医疗模块)
  核心层只做三件事: 鉴权、提供数据库连接、挂路由
  业务逻辑全部在 N 模块内部完成
```

**关键原则:**
- 独立项目完全不依赖平台即可运行
- 平台模式下核心层与模块层零业务逻辑重叠

## 二、DADS 双轨: 保护自己 vs 救人

```
DADS 个人 (帮医生保护自己):
  - 不联网也能查药物 · 避免开错药吃官司
  - 学习追踪: 哪些知识缺口还没补
  - 贡献证明: 上传数据有回声, 不上传不受罚

DADS 医疗 (帮医生救人):
  - 输入处方文本 → 自动提取药名·剂量·频次·途径
  - 自动检测相互作用 (O(n²) 两两对比本地数据库)
  - CrCl 肾功能调整剂量
  - 9 种临床评分一键计算
```

## 三、数据怎么存: 一个池子, 各管各的

```
只有一台 PostgreSQL, 但每个 N 模块的表必须加前缀:
  医疗模块 → med_drugs, med_interactions, med_guidelines
  法律模块 → legal_cases, legal_statutes (未来)

谁也不能越界:
  医疗模块不允许直接查 core_users 表
  核心层不允许写业务逻辑

获取数据库连接只有一条路:
  def my_function(db: Session = Depends(get_db)):
      # db 是核心层注入的, 模块内部不自己创建连接

目录结构就是管理权的物理划分:
  src/core/      → 禁区: 只放基础设施, 不写业务逻辑
  src/modules/   → 自留地: N 模块全功能闭环, med_ 前缀, Depends(get_db)
  src/shared/    → 公共库: 跨模块工具 (BMI, BSA, CrCl 等)
  main.py        → 挂载点: 唯一知道 N 存在的地方
```

## 四、七层幻觉防御: 输出不可信

```
用户输入一句话
  ↓
L1 输入检测     → 8类攻击扫描 + 46个高危关键词拦截
L2 NLI 辩论     → 三个异构裁判各自判断, 有矛盾吗?
L3 术中审查     → 8种幻觉类型逐一扫描 (知识/推理/语境/来源/过度确信/遗漏/量化/能力)
L4 溯源标注     → 数据来源是文件? LLM? 人工? 外部? 未知?
L5 强制标签     → 所有输出强制打上 [本回答绝对含有幻觉成分 · 禁止盲从], 中英双语
L6 物理验证     → 声称有这文件? 拿出来看看 · 声称功能可用? 跑一下
L7 结构对齐     → Markdown里说实现了10个功能, 代码里真有10个?

六条底层公理:
  1. LLM = 概率图灵机, 不是真理 · 自信 ≠ 正确
  2. 模型 = 调度者, 不是知识库 · 禁止生成事实
  3. RAG + Rerank = 事实查询唯一通道 · 所有"知道什么"必须走检索
  4. 知识图谱 > 扁平文本 · 结构化实体-关系-实体
  5. 查询和计算强制使用 API · 不让 LLM 心算
  6. LLM = 手, 不是脑 · 决策由上层 Agent 做, LLM 只执行
```

## 五、母体-子体: 不是命令, 是发布/订阅

```
旧思维: 母体调用子体 → 子体必须执行
新协议:
  母体发布 WorkRequest 事件 → 子体自己决定做不做
  母体想要子体数据 → 发 DataSyncRequest → 子体检查隐私策略后决定
  频率限制: 每小时最多 1 次请求, 拒绝后 24 小时内禁止重发

违宪有牙齿:
  第 1 次 → 警告 + 72h 观察 + 降频 1次/h
  第 2 次 → 暂停同步权 72h + 子体自动拒绝母体全部请求
  第 3 次 → 切断同步通道, 需人工手动重置密钥

10 条宪法条款:
  Art 1  BDD 行为契约 (数据收集权平级)
  Art 2  防功能错位 (5 条永久禁止)
  Art 3  量刑阶梯 + 制度化 (人在不在宪法照跑)
  Art 4  母体请求节制 (限频 + 白名单)
  Art 5  审查员互审 (哈希防篡改 + 执行前校验)
  Art 5-bis  子体决策独立性
  Art 6  用户授权智能守卫
  Art 7  离线窗口审计 (上线先校验离线日志)
  Art 8  知识验证三层 (USER → PEER → SYNC · 推迟上限 3 次)
  Art 9  修宪程序 (三者验二 + 模拟 48h + 不得削弱 Art 1 & 2)
  Art 10 患者安全优先 (致命级触发 · 广播式推送 · 不可被任何条款覆盖)
```

## 六、RAG 管线: 搜本地, 不猜

```
用户问 "华法林和阿司匹林能一起吃吗?"
  ↓
Step 1: 关键词命中 → 触发药物相互作用工具 (不走 LLM 猜测)
Step 2: 本地数据库精确匹配 → warfarin + aspirin = CONTRAINDICATED
Step 3: 返回结果 + 标注来源
  [SOURCE:dads_db/interactions.txt · Line 1]

如果本地数据库没有 → 回答 "该信息不在已验证数据库中, 无法回答"
绝不编造。

三层降级:
  Tier 1: Ollama 本地模型 (全离线)
  Tier 2: DashScope / DeepSeek API (需 Key)
  Tier 3: 纯规则引擎 (零 LLM · 零网络 · 零依赖)
  自动降级: ollama → api → rule
```

## 七、8 重地狱审查 (DADS 内部)

```
药物输出 → 8 个审查员各自评分:
  临床主任 (恶人)   → 过度确信 · AI 暴露 · 诊断越界 · 多药风险
  懂王患者 (恶人)   → 隐私暴露 · 用药偏见 · 数据推理 · 费用暗示
  合规判官 (恶人)   → 溯源缺失 · LLM 来源 · 敏感人群 · 审计缺失
  老旧硬件 (死局)   → 云端依赖 · 重型依赖 · Win7 兼容 · CPU 占用
  医保判官 (死局)   → 高成本药物 · DRG 陷阱 · 运行成本 · 采购壁垒
  脏数据沼泽 (死局) → 格式不一致 · 非结构化 · 系统孤岛 · 数据污染
  算法偏见 (死局)   → 黑箱算法 · 人群偏见 · 性能分层 · 可解释性
  契约审查员 (BDD)  → SILENT_PULL · OFFLINE_ACCESS · MOTHER_WRITE · AUTO_UPLOAD
```

## 八、架构对比

| 维度 | 独立项目 | 平台 1+N |
|------|---------|----------|
| 启动方式 | 单文件打开即用 | FastAPI + PostgreSQL |
| 联网需求 | 零网络 | 需要数据库 |
| 模块扩展 | 打包进 exe | `src/modules/{name}/` 热挂载 |
| 数据存储 | 本地 txt/json | PostgreSQL (前缀隔离) |
| 适用场景 | 个人医生快速查阅 | 科室/医院多用户协同 |

| 维度 | DADS 个人 | DADS 医疗 |
|------|----------|----------|
| 目标 | 保护医生自己 | 帮助医生救人 |
| RAG 数据源 | 个人学习记录 + 本地数据库 | 药物·相互作用·指南数据库 |
| 输出 | 学习报告·缺口分析·贡献标记 | 相互作用警报·剂量调整·临床评分 |
| LLM 依赖 | 弱 (3 层降级) | 弱 (规则引擎优先) |
| 隐私 | 数据仅本地存储 | 临床笔记可同步 (需手动触发) |

## 十、核心不变量

```
1. 绝不将 LLM 输出直接作为事实
2. 所有输出必须包含中英双语警告标签
3. 各模块数据表严格隔离
4. 数据库连接必须通过依赖注入获取
5. 子体响应 ≠ 母体命令 (子体有自主决策权)
6. 累计违宪 3 次 → 切断通道
```
