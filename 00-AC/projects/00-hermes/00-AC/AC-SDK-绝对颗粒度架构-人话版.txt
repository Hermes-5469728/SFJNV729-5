一、核心概念（图解版）
================================================================================

1.1 Atelier 是什么？
--------------------------------------------------------------------------------

Atelier = 一个「AI 医疗决策辅助系统」的完整架构框架。

把它想象成一栋大楼：
- T = 地基和楼层结构（双轨：独立运行 or 平台集成）
- M = 各楼层的房间功能（DADS-Medical 诊断室、DADS-Personal 服务台、Gaia 消防系统）
- D = 楼层之间的电路管道（数据隔离、互不干扰）
- G = 物业管理和消防规则（谁可以用什么、违规怎么处理）


1.2 双轨制 T（两条腿走路）
--------------------------------------------------------------------------------

┌─────────────────────────────────────────────────────┐
│  独立模式 Standalone          平台模式 Platform     │
│  ───────────────────          ─────────────────     │
│  可以单独运行                  接入大平台运行        │
│  例: 单机版 DADS              例: AC Platform 集成 │
│                                                     │
│  特点: 自给自足                特点: 共享资源        │
│  启动快、功能全                扩展强、依赖平台      │
└─────────────────────────────────────────────────────┘

人话: 要么自己买房独立住，要么住公寓和别人共享资源。

================================================================================

--------------------------------------------------------------------------------

| 模块            | 类比           | 功能                               |
|-----------------|----------------|------------------------------------|

2.2 Gaia 七层防火墙（重点）
--------------------------------------------------------------------------------

想象一个「AI 说话审核流程」：

用户输入
   │
   ▼
┌─────────────────────────────────────────┐
│  L1 入门安检 ─── 格式对不对？长度正常？  │
│       │                                  │
│       ▼                                  │
│  L2 辩论环节 ─── 这话有没有逻辑矛盾？    │
│       │                                  │
│       ▼                                  │
│  L3 专业审查 ─── 医学内容合规吗？        │
│       │                                  │
│       ▼                                  │
│  L4 溯源检查 ─── 数据从哪来的？          │
│       │                                  │
│       ▼                                  │
│  L5 强制标注 ─── 必须声明「我不一定对」  │
│       │                                  │
│       ▼                                  │
│  L6 物理验证 ─── 数字算对了吗？          │
│       │                                  │
│       ▼                                  │
│  L7 最终确认 ─── 可以输出了吗？          │
└─────────────────────────────────────────┘
        │
        ▼
    用户看到输出 + 幻觉声明

任一层卡住 = 整个请求被拒


三、数据层 D（表名前缀隔离）
================================================================================

3.1 为什么隔离？
--------------------------------------------------------------------------------

类比：医院里病历系统、药品系统、财务系统的数据库绝对不能混用。


3.2 命名规则
--------------------------------------------------------------------------------

模块前缀_表名 = 完整表名

med_drugs          ← 医疗-药品表
med_interactions   ← 医疗-相互作用表
per_worklog        ← 个人-工作日志表
gaia_audit         ← 防御-审计表
audit_chain        ← 审计-哈希链表

好处: 无论谁写 SQL，都不会不小心动到别人的数据。


四、治理层 G（物业管理规则）
================================================================================

4.1 母体-子体协议
--------------------------------------------------------------------------------

母体(Hermes/用户)
   │
   发布命令(发布/订阅模式)
   │
   ▼
子体(AC SDK/AI Agent)
   │
   响应（可以拒绝）
   │
   ▼
审计链记录

关键: 子体不是傀儡，可以拒绝不合理命令。


4.2 BDD 违宪检测
--------------------------------------------------------------------------------

BDD = Behavioral Deviation Detection（行为偏离检测）

类比：宪法规定「不得歧视患者」，AI 说了歧视性言论 → 违宪 → 触发惩罚。


4.3 量刑阶梯
--------------------------------------------------------------------------------

第一次违规 → 警告 (WARN)
第二次违规 → 暂停 (SUSPEND)
第三次违规 → 断连 (SEVER) ← 永久踢出


4.4 八重地狱（内部质量审查）
--------------------------------------------------------------------------------

5 个维度的审查全部通过才算合格：
1. 事实准确性
2. 逻辑一致性
3. 医学合规性
4. 法律合规性
5. 伦理合规性

六、关键技术选型（为什么用这个？）
================================================================================

6.1 选型决策表
--------------------------------------------------------------------------------

| 场景       | 选型                    | 原因                                 |
|------------|-------------------------|--------------------------------------|
| 向量检索   | BGE-M3 + Qdrant         | 效果好、自动 fallback                |
| 离线 fallback | TF-IDF               | 零依赖、网络断了自己顶上              |
| 安全扫描   | LLM-Guard               | 开源成熟、社区维护                    |
| 对话记忆   | Mem0                    | 专注长期记忆管理                      |
| 熔断器     | pybreaker               | 工业级、状态机完善                    |
| 模型路由   | LiteLLM                  | 一个接口调所有模型                   |


6.2 降级链设计
--------------------------------------------------------------------------------

请求进来
   │
   ▼ try Ollama (本地)
      │
      ▼ 失败
      ▼ try DashScope (阿里云)
         │
         ▼ 失败
         ▼ try DeepSeek (深度求索)
            │
            ▼ 失败
            ▼ return RuleEngine (规则引擎兜底)

人话: 能用好模型用好模型，不行了逐级降级，最后还有规则引擎保底。


七、不变量（铁律 · 绝对不能违反）
================================================================================

| # | 铁律                           | 类比                               |
|---|--------------------------------|------------------------------------|
| 1 | LLM 输出不能直接当事实          | 实习生报告必须主管审核             |
| 2 | 所有输出必须带幻觉声明          | 天气预报员必须说「可能不准」       |
| 3 | 表名必须带前缀隔离              | 医院各科室病历不能混放             |
| 4 | DB 操作必须依赖注入             | 维修必须走物业申请                 |
| 5 | 子体响应 ≠ 母体命令             | 员工可以拒绝违法的命令             |
| 6 | 三犯违宪立即 SEVER              | 第三次违规直接开除                 |


八、快速参考（速查卡）
================================================================================

8.1 问：这个系统怎么工作？
--------------------------------------------------------------------------------
用户输入 → Gaia 七层审核 → DADS 检索 → LLM 生成 → 双语标注 → 用户输出


8.2 问：数据怎么存储？
--------------------------------------------------------------------------------
每个模块 → 前缀_表名
例: med_drugs, per_worklog


8.3 问：模型挂了怎么办？
--------------------------------------------------------------------------------
Ollama → DashScope → DeepSeek → RuleEngine


8.4 问：AI 胡说八道怎么办？
--------------------------------------------------------------------------------
Gaia 七层防火墙
+ LLM-Guard 扫描
+ BDD 违宪检测
+ 强制幻觉声明


8.5 问：想扩展新模块？
--------------------------------------------------------------------------------
1. 取个前缀名 (med_xxx, per_xxx)
2. 遵守接口协议
3. 通过 Gaia 审核
4. 写入 ADR 决策记录

十、Q&A（常见问题）
================================================================================

Q: 为什么叫「绝对颗粒度」？
A: 每一条规则、每一个模块、每一个表名都定义得清清楚楚，没有模糊地带。


Q: 为什么需要这么多层审核？
A: 医疗场景不允许出错。宁可慢一点、严格一点，也不能让错误信息害了患者。


Q: Hermes 不写代码，谁来写？
A: AI 写。Hermes 只做架构决策和质量把关。


Q: 万一系统被攻击了怎么办？
A: L0-LLM-Guard 前置扫描 → L3-BDD 违宪检测 → SHA256 审计链追踪 → 三犯断连。
