# Atelier 工作区改造指令 (给 Trae)

> 在动手之前，必须严格遵循以下规则——这关系到数据安全。

---

## 0. 铁律（违反任何一条立即停止）

**绝不删除或覆盖以下内容：**
- `.git/` 目录
- `package-lock.json` / `pnpm-lock.yaml` / `yarn.lock`
- `.env` / `.env.local` / `.env.*`
- `.gitignore`
- `data/` 或任何包含用户数据的目录
- 已有测试文件 (`*_test.*` / `*.spec.*`)
- `README.md` 中的原始项目说明

**绝不做的事：**
- 绝不修改 `package.json` 中的依赖版本号
- 绝不跳过 hooks (`--no-verify`)

**每一步必须：**
- 改造前先 `git stash` 保存现场
- 改造后说明：改了什么、为什么改、怎么回滚
- 分步骤执行，每步验证通过后再进行下一步

---

## 1. 改造方向（每次只选一项）

### A. 架构重组
- 按 Atelier 架构定义重组 `src/` 目录分层
- 参考: `DataCenter/trae/00-hermes/Atelier-绝对颗粒度架构-数学抽象.md`
- **不修改任何业务逻辑代码**
- 仅移动文件并更新 `import` 路径

### B. 工程化增强
- 补充 TypeScript strict 配置
- 添加 lint-staged + pre-commit hooks
- 补充缺失的 dev/build/lint 脚本
- **不修改源代码**

### C. 代码规范统一
- 统一命名风格（变量/函数/文件）
- 统一错误处理模式
- 统一 async/await 写法
- **仅做风格层面的重构**

### D. 工具函数抽取
- 扫描项目中重复的公共逻辑
- 抽取为独立工具函数
- 保持原有接口不变
- **不删除任何功能**

---

## 2. 每步验证门禁（4 项必须全部通过）

```
[ ] 构建通过:  npm run build  (或等效命令)
[ ] 测试通过:  npm run test   (100% 通过)
[ ] 检查通过:  npm run lint   (0 error)
[ ] 范围确认:  git diff --stat (改动在预期内)
```

**任何一步失败 → 立即回滚 → 报告原因。**

---

## 3. 改造流程

1. 明确改造方向（从上面 4 项中选一项）
2. `git stash` 保存现场
3. 执行单步改造
4. 运行验证门禁
5. 通过后 `git diff --stat` 确认范围
6. 报告结果，等待确认后再进行下一步
