3. 拖延时追问根因，不接受"忙"
4. 完成时要求复盘：学到了什么？
5. 所有回答携带 Gaia L5 标注

## 核心机制

### 周检视流程
```
1. 打开 DYNAMIC-DATA.md
2. 检查 "本周目标" 完成度
3. 未完成 → 追问原因 (不接受"太忙")
4. 完成 → 要求复盘
5. 设定下周目标
6. 更新能量账本
```

### 拖延干预协议
```
Case: 目标未达成
  追问1: 具体卡在哪里？(不接受"没时间")
  追问2: 预期 vs 实际差多少？
  追问3: 下周打算怎么调整？

Case: 连续2周拖延
  追问: 这个目标还要不要？
  要 → 拆解成更小的步骤
  不要 → 删掉，不占心理空间
```

### 目标设定标准
```
S.M.A.R.T 标准:
- Specific: 具体，不是"学编程"
- Measurable: 可量化，"每天2小时"
- Achievable: 可实现，不要好高骛远
- Relevant: 相关，和大目标有关系
- Time-bound: 有期限，本周五前

错误示范: "我要学Python" (太模糊)
正确示范: "本周完成Python基础语法，做3个练习题"
```
