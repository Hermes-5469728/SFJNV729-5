# AC Platform 项目交接文档

## 一、项目概述

### 1.1 项目名称
AC Platform — 1+N 双轨架构临床决策支持系统

### 1.2 架构理念
- **1+N 双轨架构**：1 个核心平台 + N 个插件化模块
- **寄生/独立双模启动**：模块可独立运行，也可寄生在核心平台上
- **数据隔离策略**：模块间数据库表前缀隔离（如 `med_`），核心数据不可被模块直接访问

### 1.3 项目结构

## 二、核心层说明 (src/core/)

### 2.1 config.py — 全局配置
- `AC_CORE_MODE`：核心平台开关（True = 航母模式，False = 独立模式）
- `DATABASE_URL`：SQLite 数据库连接字符串
- `MOTHER_CITY/PROVINCE`：时空锚定（当前：仙桃市/湖北省）
- `OLLAMA_HOST`：本地 LLM 服务地址
- `DASHSCOPE_API_KEY` / `DEEPSEEK_API_KEY`：云端 LLM API Keys

### 2.2 database.py — 唯一数据库连接池
- 使用 SQLAlchemy `create_engine` 创建单一引擎
- `SessionLocal`：线程安全的 session 工厂
- `get_db()`：FastAPI 依赖注入函数
- `init_db()`：启动时自动创建所有模块表

### 2.3 auth.py — API Key 鉴权
- 使用 `X-API-Key` 请求头
- 无 API_KEY 时自动进入 dev_mode（不鉴权）
- 返回 "authenticated" 或抛出 401

### 2.4 router.py — 工具注册中心
- `RouteMode`：DETERMINISTIC（确定性路由）| HEURISTIC（启发式路由）
- `ToolRegistry`：全局工具注册表
- 支持按 module 筛选工具列表

### 2.5 gaia_defense.py — Gaia 统一防御管道
- **SemanticCache**：语义相似度缓存（阈值 0.45，200 条上限）
- **HIGH_RISK_KEYWORDS**：46 个高风险关键词
- **JAILBREAK_PATTERNS**：4 种越狱模式检测
- **RecursionGuard**：递归防护（A/B/C 三级自适应截断）
- **EfficacyTracker**：7 天 kill_rate 追踪
- **GaiaDefensePipeline.process()**：统一入口，返回 blocked/layers/timing_ms

## 四、医疗模块说明 (src/modules/medical/)

### 4.1 数据模型 (models.py) — 强制 med_ 前缀

| 表名 | 用途 |
|------|------|
| `med_drugs` | 药物主数据 |
| `med_interactions` | 药物相互作用 |
| `med_guidelines` | 临床指南 |
| `med_safety_alerts` | 安全警示 |
| `med_user_profiles` | 用户画像 |

### 4.2 临床评分引擎 (scores.py) — 9 种评分

| 评分 | 用途 | 关键参数 |
|------|------|----------|
| cha2ds2_vasc | 房颤卒中风险 | age, sex, chf, htn, stroke, dm, vascular |
| has_bled | 抗凝出血风险 | htn, renal, liver, stroke, bleed, inr, age, alc, asa |
| wells_dvt | 深静脉血栓 | cancer, bed, calf, collat, leg, pit, prev, alt |
| wells_pe | 肺栓塞 | dvt, pe, hr, immob, prev, hemoptysis, cancer |
| curb65 | 社区获得性肺炎 | confusion, bun, rr, bp, age65 |
| gcs | 格拉斯哥昏迷量表 | eye, verbal, motor |
| child_pugh | 肝功能分级 | bili, alb, inr, ascites, enceph |
| timi_nstemi | 非 ST 段抬高心梗 | age, cad, asa, angina, st, marker |
| abcd2 | 短暂性脑缺血发作 | age, bp, clin, dur, dm |

**CrCl 剂量调整**（5 种药物）：
- metformin、enoxaparin、dabigatran、rivaroxaban、apixaban

### 4.3 本地防御适配器 (defense.py)

- **DADSRequiredDBs**：4 个必需数据库（drugs/interactions/guidelines/safety）
- **GUIDELINE_WINDOW_DAYS**：90 天指南新鲜度窗口
- **detect_intent_risk()**：L1 意图风险检测
- **DADSDefenseProcessor.process()**：返回 blocked/layers/timing_ms
- **强制标签**：`[本回答绝对含有幻觉成分 · 禁止盲从 · 外部验证前不可采信]`

### 4.4 3 层 LLM 降级策略 (llm.py)

| 层级 | 提供商 | 模型 | 优先级 |
|------|--------|------|--------|
| L1 | Ollama（本地） | qwen2.5:7b | 最高（优先） |
| L2 | DashScope（阿里） | qwen-turbo | 次优先 |
| L3 | DeepSeek | deepseek-chat | 最后兜底 |

- `generate()`：自动遍历可用提供商，失败后自动降级
- 内置 response cache（按 prompt 前 500 字符去重）
- `stats_summary()`：返回 total/cache_hits/error/cache_size

### 4.5 向量存储 (vector.py) — 零依赖

- **无 faiss 依赖**：纯 Python 实现
- **TF-IDF Cosine 相似度**：中英混合 tokenization
- **add() / search() / delete()**：增删查接口
- **init_vector_store()**：自动从 drugs.txt 初始化

### 4.6 API 路由 (api.py)

| 端点 | 方法 | 说明 |
|------|------|------|
| `/medical/drugs` | GET/POST | 药物列表/创建 |
| `/medical/drugs/{name}` | GET | 获取单个药物 |
| `/medical/interactions/check` | POST | 检查两种药物相互作用 |
| `/medical/interactions/{name}` | GET | 获取某种药物的所有相互作用 |
| `/medical/scores/calculate` | POST | 计算临床评分 |
| `/medical/scores/crcl_adjustment/{drug}` | GET | CrCl 剂量调整查询 |
| `/medical/guidelines/search` | POST | 搜索临床指南 |
| `/medical/safety/{drug}` | GET | 获取安全警示 |
| `/medical/safety/alerts` | POST | 创建安全警示 |
| `/medical/defense/check` | POST | 防御管道检测 |
| `/medical/defense/status` | GET | 防御状态 |

## 七、设计原则回顾

1. **1+N 双轨**：核心不可知模块，模块不可直接访问核心资源
2. **数据隔离**：所有模块表使用模块前缀（med_）
3. **寄生/独立双模**：模块可独立运行，核心平台可选
4. **零幻觉**：所有输出必须携带强制标签，医疗内容必须外部验证
5. **本地优先**：LLM 降级、向量存储、防御管道均优先本地实现
6. **合规前置**：MOTHER_CONSTITUTION Article 0.8 强制本地法规检查
