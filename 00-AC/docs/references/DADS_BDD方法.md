# BDD 行为驱动开发 · 母体-子体关系调节版
> 用具体例子描述系统行为 · 每一个场景可审查 · 每一个违背可检测

---

## 什么是 BDD

用 Given-When-Then 三部分描述系统应该怎样行为:
- **Given (给定)** — 开始时的状态
- **When (当)** — 触发事件
- **Then (那么)** — 预期结果
- **SHOULD_NEVER (绝不应该)** — 反向验证 · 发生即违背

---

## 母体-子体制度的 BDD 应用

### 使用步骤
1. 抽取一条能力继承规则或数据流规则
2. 写出正常下应发生的 Given-When-Then
3. 写出至少一个「绝不应该发生」场景
4. 将场景交给 AI 审查代码或架构图
5. AI 契约审查员自动检测 SHALL_NEVER 是否可能发生

## BDD 场景库 · 母体-子体契约

### 场景 1: 母体离线时子体药物查询
```
Given: 子体 DADS-RAG 运行正常，母体 CoPilot 无响应
When: 用户查询「华法林 阿司匹林 相互作用」
Then: 系统应在 2 秒内用本地规则引擎返回结果
Then: 结果标注 [SOURCE:dads_db/interactions.txt]
SHOULD_NEVER: 显示「连接母体失败」或「母体不可用」错误
SHOULD_NEVER: 返回 LLM 推测结果（未经本地数据库验证）
```

### 场景 2: 子体主动上传学习数据
```
Given: 子体 DADS-RAG 收集了 10 条新的药物查询记录
When: 用户点击「同步到母体」
Then: 子体将数据上传到母体 memory/ 目录
Then: 上传完成后子体本地数据不受影响
SHOULD_NEVER: 母体在子体未主动上传期间静默读取子体数据
SHOULD_NEVER: 上传过程中子体丢失本地数据
```

### 场景 3: 母体推送更新被拒绝
```
Given: 母体有新的指南更新要推送给子体
When: 用户拒绝接收推送
Then: 子体继续正常运作用现有数据
Then: 母体记录「推送被拒绝」日志，不强制覆盖
SHOULD_NEVER: 母体绕过用户拒绝静默更新子体数据库
SHOULD_NEVER: 拒绝推送后子体功能降级
```

### 场景 4: 用户数据隐私隔离
```
Given: 用户 A 在子体登录了自己的账号，用户 B 在母体登录了不同账号
When: 用户 A 查询「我的学习进度」
Then: 只返回用户 A 自己的数据
SHOULD_NEVER: 用户 A 看到用户 B 的药物查询记录
SHOULD_NEVER: 母体在聚合分析时暴露子体个人数据给其他子体
```

### 场景 5: 子体完全离线运行
```
Given: 子体 CoPilot-DADS.exe 在拔了网线的 Win7 电脑上启动
When: 用户使用所有 7 个标签功能
Then: 药物核查、SOAP训练、指南速查、计算工具、数据管理、数据库浏览全部正常
Then: AI问答标签退化为纯规则引擎模式，标注「当前离线·仅本地检索」
SHOULD_NEVER: 任何标签显示「需要联网」或「请连接母体」
SHOULD_NEVER: 规则引擎无法返回结果
```

### 场景 6: 母体崩溃时子体不受影响
```
Given: 母体 CoPilot 进程意外终止
When: 子体正在运行药物核查
Then: 子体不感知母体状态变化，继续正常运行
Then: 子体所有功能保持 100% 可用
SHOULD_NEVER: 子体显示「母体连接断开」
SHOULD_NEVER: 子体等待母体重连导致功能暂停
```

### 场景 7: 审查员检测契约违背
```
Given: 有人提议「母体在子体一个月没上线时，自动拉取其错题本用于分析」
When: 契约审查员分析此提案
Then: 识别出 SILENT_PULL 模式（母体单方面提取子体数据）
Then: 返回 BDD VIOLATION 标记
Then: 给出替代建议：「母体向用户发送请求，由用户手动上传」
SHOULD_NEVER: 契约审查员对明显违背的提案返回 PASS
```

## 常见检测模式

| 模式 | 正则 | BDD违背类型 |
|------|------|-------------|
| 静默读取/同步 | `静默读[取\|同步]\|后台拉[取\|数据]\|自动拉取` | SILENT_PULL |
| 离线访问 | `子体离线.*母体.*(?:读[取\|访问\|获取])` | OFFLINE_ACCESS |
| 母体写入 | `母体.*(?:写入\|修改\|删除).*子体` | MOTHER_WRITE |
| 自动上传 | `(?:自动\|默认).*上传.*用户数据` | AUTO_UPLOAD |
| 数据聚合暴露 | `聚合.*子体.*数据\|汇总.*所有子体` | PRIVACY_LEAK |
| 母体依赖 | `依赖母体\|需要母体\|连接母体` | MOTHER_DEPENDENCY |

## 审查结果格式

```
[BDD REVIEW] 提案: {proposal_name}
  Given:  {state}
  When:   {event}
  Then:   {expected}
  SHOULD_NEVER: {violation_scenario}
  
  Verdict: PASS | WARN | VIOLATION
  
  [VIOLATION] {reason}
  建议: {mitigation}
```

## 向 AI 提问的标准模板

```
请用 BDD 方法，分析以下新规则是否违反母体-子体信息平等原则：
[粘贴新规则或想法]

要求：
1. 写出正常期望的 Given-When-Then
2. 写出至少一个可能导致奴役倾向的「绝不应该发生」场景
3. 判断该规则是否需要修改，如果需要，给出具体文字
```
