## 零、是什么

**DADS-RAG AGENT** 是 CoPilot 母体下的唯一子体。全称为 **Drug Analysis & Decision System + Retrieval-Augmented Generation Agent**。

它不是通用 AI。不是 ChatGPT 医疗版。它是：
- **确定性**（规则引擎查本地 txt） + **可溯源**（每条标出处） + **个性化**（学习路线 · 个人数据库）
- 三者重叠区。没有别人同时做这三件事。

## 二、宪法 · Constitution

### 四条底层认知

1. **查药 ≠ 猜药** — 规则引擎查本地 txt——不是 LLM 推测。确定性 > 覆盖率。
2. **全离线 ≠ 落后** — 医院内网拔了网线——这是设计约束 · 不是技术限制。
3. **溯源 = 可信** — 每条答案标出处——打开源文件就能核实。不靠背书。
4. **DADS是工具 · 不是医生** — 不诊断 · 不开药 · 不替人做决定。输出末尾强制标注。

### 核心目标

1. **查对药** — 31种药 · 120组相互作用 · 17条指南 · 3秒返回
2. **不出错** — 规则引擎零幻觉 · LLM部分强制标注 · 不编数据
3. **零门槛** — exe双击即用 · 不需要 Python · 不需要网络 · 不需要注册

## 三、架构 · Architecture

### 四层体系

```
第一层 · 本地数据层 · dads_db/
  drugs.txt · interactions.txt · guidelines.txt · safety.txt
  policy_drg.json · policy_reality.json · drg_rules.json · fhir/
  全部txt/json · 人类可读 · 药房主任能打开 · 每行可git diff

  crcl_adjustment(29种药·4级分层) · clinical_scores(9个评分)
  drg_predict()
  全部规则引擎 · 零LLM · 零幻觉 · 结果标注[VERIFIED]

第三层 · 检索增强 · 离线RAG · <50ms
  TfidfVectorizer(char_wb·1-3gram·2000维) · cosine_similarity · top-k=5
  260条chunk · DADSVectorStore(零依赖numpy版)
  全离线 · 零下载 · <50ms

  DashScope Qwen-Plus(主) · DeepSeek(备) · Ollama(本地)
  temperature=0.3 · max_tokens=1024 · 3次指数退避(1s/2s/4s)
  无API时自动退化为纯规则引擎

第五层 · 审查体系 · 8重地狱自我审查

  对DADS回答进行交叉验证 + BDD契约违背自动拦截 · 不依赖母体

第六层 · 治理 · 母体宪法 Art 1-10
  BDD行为契约 · 防功能错位 · 量刑阶梯 · 请求节制 · 审查员互审
  用户智能守卫 · 离线审计 · 知识三层验证 · 修宪程序 · 患者安全优先(Art 10)

第七层 · 个人定制化
  寄生笔记法 · 学习路线 · 文件上传 · 个人数据库 · 时间守护 · 进度追踪 · 贡献证明
```

## 七、边界 · Boundaries

### DADS会做的
- 精确查药（规则引擎 · 确定性）
- 检查相互作用（O(n²)全量匹配 · 120组数据库）
- 提供指南要点（17条A级证据 · 标出处）
- 计算临床评分（9个工具 · 带风险分层）
- 个性化学习路线 · 寄生笔记同步
- 8重地狱自我审查 · 契约审查(BDD)
- 贡献证明(上传验证→标记+优先接收)

### DADS不会做的
- 编造药物（没有就是没有 · 不对就是不对）
- 替代医生诊断（不推测病情 · 不推荐治疗方案）
- 联想推理（你说A · 它不猜B · 不主动扩展）
- 联网搜索（全离线 · 数据就是本地文件）
- 自学习（不自动修改数据库 · 手动添加才生效）

### DADS不知道的
- 你的医院的具体医保目录（需要你上传）
- 最新一周刚发布的指南（需要人工更新txt）
- 患者的具体病情（DADS只看文本 · 不看人）

## 九、常见疑问与回应

> DADS在交流中遇到过的各类问题，整理如下供参考。

1. "看不懂技术，所以没用。"  
→ drugs.txt 在 dads_db/ 文件夹里——用记事本就能打开。

2. "不联网你怎么查数据？"  
→ 查的是本地文件，不是网络。离线不是技术限制，是设计选择。

3. "AI不可信。"  
→ 这也是DADS默认的前提。规则引擎之所以存在，就是为了不依赖AI生成，而是查本地文件。

4. "31种药太少了。"  
→ 每一行都有人工验证的来源。数量不追求多，追求每一行都有出处。

5. "你怎么保证准确？"  
→ 不用保证。打开 interactions.txt，每一行都有来源标注。不信可以核对。

6. "你是领导你说不行。"  
→ 你有权决定用不用。但 txt 文件里的相互作用不因为决定而改变。如果不用，需要提供一个替代方案。

7. "需要审批才能落地。"  
→ 谁来审批？标准是什么？把这些说清楚，流程可以走。

8. "先放一放。"  
→ 放多久？具体等什么条件？

9. "预算不够。"  
→ 免费。不需要预算。

10. "需要信息科评估。"  
→ 不需要安装，不需要联网，不需要管理员权限。评估什么？

11. "反对意见是"再看看"。"  
→ 从 v19.0 到 v19.4，9天迭代。具体还需要看什么？

12. "没有收费编码不能在医院用。"  
→ 可以用。exe在U盘里就能跑，不需要医院信息系统。

13. "怎么保证患者隐私？"  
→ 不联网，不上传，不存储患者姓名。数据在本机。

14. "我说不行就是不行。"  
→ 你是对工具说不，不是对事实说不。事实在那里，工具也在那里。

15. "需要全院讨论。"  
→ 讨论一个 txt 文件？讨论的议程和标准是什么？

16. "等信息系统建好。"  
→ 信息系统建好之前，查药这件事不能停。DADS今天就能用。

17. "不符合年度计划。"  
→ 年度计划里有没有"医疗安全"这一条？减少药物差错属于医疗安全。

18. "需要伦理审查。"  
→ 审查一个 txt 文件？标准是什么？

19. "怕担责，不想用新工具。"  
→ 理解。所以DADS不替代你的判断，只提供查到的数据。决策还是你的。

20. "AI给的建议不放心。"  
→ DADS不是AI，是规则引擎。规则引擎不会编——它只会查。

21. "你工作几年？"  
→ 和 warfarin+aspirin 的相互作用有关系吗？

22. "太理想化了。"  
→ 减少药物差错不是理想主义。

23. "太较真了。"  
→ 药物相互作用是会死人的。

24. "低调用不行吗？"  
→ DADS不争存在感。打开 txt，查完药，关掉。不需要任何人注意到。

25. "沉默也是一种回应。"  
→ 沉默改变不了 txt 文件里的内容。工具在那里，需要的时候可以打开。

26. "出了事谁担责？"  
→ DADS不是医生，不开药，不诊断。它只查数据。判断和决策是医生的事。

27. "没有医师资格证。"  
→ 查药不需要资格证。需要的是准确的数据库。

28. "你这是非法行医。"  
→ 查药不是行医。把工具当替代医生的人才有问题。

29. "如果文件写错了怎么办？"  
→ 你来改。密码 dads2026。打开文件，改掉错误，系统立刻生效。

30. "被禁了怎么办？"  
→ exe可以被删掉，txt可以被删掉。但查对药的方法不会被删掉。有人记得就能重建。

31. "AI是不是会歧视某些患者？"  
→ DADS不用AI做判断。规则引擎对所有人给出相同的结果。

32. "训练数据有没有偏见？"  
→ DADS不训练。数据是人工编写的 txt 文件。

33. "老年人用不了这么复杂的工具。"  
→ 比Excel简单。双击exe，输入药名，回车。

34. "年轻人太激进。"  
→ 用 txt 文件查药算激进——那背错相互作用直接开药算稳重吗？

35. "不信任来源不明的数据。"  
→ 每一行都标注了来源。FDA/ACC/ESC/ADA——你信哪个？哪个不信？

36. "能不能做成手机版？"  
→ 目前是 exe。手机版需要额外开发。

37. "能不能接入医院的HIS系统或内网？"  
→ 当前版本全离线，不直接对接。未来在用户授权下可接入专用网络——但数据裁决权始终在子体侧，Art 8约束。

38. "能不能支持更多药？"  
→ 能。打开 drugs.txt，按照格式添加新药即可。

39. "数据会不会过时？"  
→ 会。每季度需要人工更新 guidelines.txt。这是全离线设计的代价。

40. "你是不是在推销？"  
→ 免费。开源。不需要注册。不需要联网。不需要服务费。

41. "没人会用怎么办？"  
→ 有人需要就会用。DADS不追求用户量，追求需要它的人能用上。

42. "功能太少。"  
→ DADS只做一件事：查药查准。如果还需要其他功能，欢迎提。

43. "和丁香园/UpToDate比怎么样？"  
→ 丁香园和UpToDate需要联网、需要订阅。DADS离线免费。没有替代关系。

44. "你怎么证明你查得对？"  
→ 不用证明。打开文件自己看。每一行都有出处。

45. "我怕被笑话用免费工具。"  
→ 用错药被笑话，还是用对工具被笑话——哪个更严重？

46. "上级不同意。"  
→ 那就自己用。exe在U盘里，不需要部署。

47. "科室不同意。"  
→ 同上。

48. "同事会怎么想？"  
→ 如果你查对了一次相互作用、避免了一次错误——同事会感谢你。

49. "万一真的没人用？"  
→ 只要你自己用——就已经有一个人用了。

50. "有意义吗。"  
→ 有。一个人查对一次药，就可能避免一次医疗差错。

## 十、诚实标注 · 已知不足

### 当前不足（4项 · 各有计划）

1. **不能粘贴整段医嘱批量解析** → 短期扩展正则 · 中期spaCy NER · 长期PDF OCR
2. **测试覆盖不足** → 6项回归测试 · 缺RAG准确率·幻觉触发·模糊测试·失效注入
3. **指南时效** → 90天窗口 · 人工每季度检查 · 中期半自动 · 长期API同步
4. **递归守卫回退策略缺失** → 短期回退建议 · 中期输出部分结果 · 长期动态阈值

### 不是不足的东西

- **不能联网** → 设计约束 · 不是技术限制
- **药品种类有限(31+)** → 数据库靠人工维护 · 不是自动爬取
- **需要密码才能编辑数据** → 安全设计 · 不是UX缺陷
