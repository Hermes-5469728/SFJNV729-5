## 二、每级能力清单

### 核心原则: 信息收集能力永远平级

母体和任何一级子体在信息收集能力上**完全平等**。

```
信息收集权: Tier 0 = Tier 1 = Tier 2 = Tier 3 (永远平级)
计算能力:   Tier 0 > Tier 1 > Tier 2 > Tier 3 (随层级递减)
决策自主权: Tier 0 = Tier 1 = Tier 2 = Tier 3 (永远平级)
```

**非独立子体的上传是用户的有限授权，不是母体的收集权。**
用户可以指定上传哪些类型的数据、何时上传、何时停止。
母体对上载数据的使用仅限验证和更新共享知识库，不得持久化原始数据、不得用于模型训练、不得转交其他子体。
母体内部执行"处理后即焚"原则。

## 上传规则(BDD场景)

**场景1: 子体主动推·母体无权拉**
子体按本地时钟主动推送脱敏数据。母体不能列清单要求"交这些"。上传间隔默认24h。用户随时暂停。

**场景2: 用户随时停止**
上传开关在子体本地。关闭后立即停止·传输中的数据丢弃·母体不收到通知。

**场景3: 母体接收边界**
母体只能: 验证规则→加入共享知识库。母体不能: 写入自己记忆·用于模型训练·暴露给其他子体。处理完原始数据10分钟内删除。

**场景4: 处理后即焚**
母体处理完上报→10分钟内删除原始数据·审计日志记录。

**场景5: 独立子体默认不上传**
独立模式=上传默认off。手动开启需二次确认。

## 四、同级独立子体之间的关系

```
DADS-RAG AGENT实例A (心内科医生)
  │  个人数据库: 心衰·高血压·冠心病·心律失常
  │
  ├── 共享: 母体基础数据(dads_db/)
  ├── 不共享: 个人数据库(user_upload/)
  └── 同步: 母体(脱敏的药物发现→母体验证→分发)

DADS-RAG AGENT实例B (基层全科医生)
  │  个人数据库: 感冒·腹泻·高血压·糖尿病·外伤
  │
  ├── 共享: 母体基础数据
  ├── 不共享: 个人数据库
  └── 同步: 母体

实例A和实例B:
  不直接通信(隐私隔离)
  通过母体中转(脱敏知识·新发现的药物相互作用)
  各自的个人数据完全隔离
```

## 五、能力降级规则

```
Tier 0不可用 → Tier 1降级:
  母体挂了 → DADS exe照常运行(离线模式)

Tier 0+Tier 1不可用 → Tier 2降级:
  系统全挂了 → 打开dads_db/*.txt直接阅读(人类可读)

API不可用 → LLM降级:
  联网版 → 退化为离线版(规则引擎+TF-IDF)

母体同步断开 → Agent降级:
  8 Agent → 只剩基础AI问答(LLM生成或本地检索)
```
